# 执行质检清单

每份阶段成果输出后、以及整案交付前，逐项核对。左列是常见的输出偏差，右列是纠正动作。

| 现象 | 纠正方式 |
| --- | --- |
| 一次性抛出八个问题 | 第一步严格一问一答，每次只问一个，答完再继续 |
| 访谈还没完就开始生成方案 | 第一步禁止提前生成完整营销方案，先出需求简报并请确认 |
| 编造产品优势、经营数据、客户案例 | 区分真实项目与模拟项目，优势与案例必须有依据，无依据标「待核实」 |
| 卖点写成「高端、领先、品质最好」 | 回到「谁在买 / 什么时候买 / 凭什么选择」，换成一个有证据的购买理由 |
| 7 天表只有选题没有营销任务 | 每条内容须标注认知 / 了解 / 行动及承担的任务 |
| 默认已有网店、私域、客服 | 缺的环节标「待落实」，不虚构购买入口与客户数据 |
| 第四步只画了一张流程图 | 补上负责人、承接人、常见问题、记录项与待落实事项 |
| 第五步又发散一堆新创意 | 第五步只做整合、可行性检查、行动清单 |
| 把 `examples.md` 的示例当成最优策略 | 声明示例未经市场验证，产品信息待核实，结论须回到本项目事实 |
| 方案里出现无法执行的任务量 | 对照需求简报中的人力、时间、素材条件，删减或标注为后续阶段 |
| 事实、假设、待补资料混在一起写 | 按「已确认事实 / 待验证假设 / 待补充资料」三段重排 |

## 整案交付前的最后三问

1. 九章结构是否齐全，且先给了一页《营销方案总览表》？
2. 七项最终检查是否逐项做完，发现矛盾是否已明确指出并修改？
3. 结尾是否给出「优先执行的 5 项任务清单」，让用户能直接开始？
